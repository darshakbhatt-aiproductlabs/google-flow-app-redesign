# Google Flow → standalone product

An unofficial product redesign exploring what Google Flow could look like as a standalone Android app with its own pricing — decoupled from Google One — and a flagship workflow that wires NotebookLM into Flow's generation pipeline.

🔗 **Live demo:** https://darshakbhatt-aiproductlabs.github.io/google-flow-app-redesign/

## What's in this repo

Two complementary artifacts, both interactive, both viewable in any modern browser. No install required.

### 📄 PRD-as-mockup — [flow-prototype.html](https://darshakbhatt-aiproductlabs.github.io/google-flow-app-redesign/flow-prototype.html)

A scrollable Product Requirements Document where each section is illustrated by a working phone mockup. **19 phone screens across 10 chapters** with side-panel notes covering:

- The problem (Flow Beta today — bundled, bare, behind)
- Landing redesign + library with search and tags
- Playground audit (motion brush, keyframes, character library, post-gen Aleph-class toolbar, multi-shot, multi-ref)
- The flagship: **Flow from a NotebookLM** — source-grounded video generation
- Google handoffs (KEEP / OPT-IN / OUT verdict matrix)
- Trust & safety (SynthID + C2PA + face-verified cameos, no public registry)
- Pricing redo (standalone Free / Creator ₹399 / Pro ₹1,499 / Studio ₹4,999)
- KPIs, rollout phases, risks
- Scalability vision (6 axes)
- Peer maturity matrix — Flow v1.0 vs Kling 3.0, Runway G4, Pika 2.5, Sora 2, Grok Imagine, Krea, Higgsfield

### 🎮 Interactive walk-throughs — [flow-interactive-mockup.html](https://darshakbhatt-aiproductlabs.github.io/google-flow-app-redesign/flow-interactive-mockup.html)

Five end-to-end guided journeys you can actually click through. State persists across steps — credits, regens, permissions are all live.

1. **From a Notebook → published Short** (flagship · 7 steps) — pick a NotebookLM, see Gemini propose a storyboard, commit credits once, generate, regenerate one shot with a free regen, restitch and publish to YouTube Shorts
2. **Create a video → Publish to YouTube** (6 steps) — the bread-and-butter creator loop
3. **Storage cap → Progressive disclosure → Pricing decision** (4 steps, branching) — how progressive disclosure replaces force-bundling
4. **Train a character → Face verification → Safe permissions** (3 steps) — how Flow handles cameos differently from Sora
5. **Upgrade decision → Standalone Flow plans** (3 steps) — Free → Pro without routing through Google One

## The thesis in three sentences

1. Flow Beta routes every upgrade into Google One — the image/video persona subsidises 5 TB of cloud storage and Gemini-in-Gmail they don't want.
2. The playground is thin: prompt + ratio + count + duration + model picker is the entire creator surface, while every serious peer ships 3–6 more capability classes.
3. The most Google-native workflow on the table — turning a NotebookLM into a full video — isn't built yet. Wire it together and Flow plants a flag in a category no peer can ship.
